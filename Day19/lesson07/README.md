# 7차시. 실패한 질문을 보관하고 다시 보내기

## 1. 학습목표

[수업 전 안내](../TODAY_GUIDE.md)를 먼저 확인합니다.

- API 연결 실패 후에도 전송한 질문을 보관합니다.
- 같은 요청 번호로 재시도하고 성공한 대화만 남깁니다.

## 2. 중요 알고리즘 및 코드를 읽을 때 반드시 알아야 할 내용

전송 버튼을 눌렀는데 연결 오류가 나면 같은 질문을 다시 타이핑해야 할까요? 전송한 질문을 pending에 보관해 두면 같은 요청을 다시 보낼 수 있습니다.

pending은 입력 중인 초안이 아닙니다. **전송했지만 성공 응답을 아직 확인하지 못한 질문 한 건**입니다.

| 시점 | pending | 입력창 |
| --- | --- | --- |
| 아직 전송하지 않음 | None | 사용 가능 |
| 전송 후 실패 | 질문·대화 ID·요청 번호 보관 | 수정 후에는 잠김 |
| 재시도 성공 | None | 다시 사용 가능 |
| 로그아웃 | 삭제 | 로그인 화면으로 이동 |

이번 실습 버튼은 서버에 보내기 전 연결 실패를 한 번 흉내 냅니다. 실패 예약은 POST /chat에서만 pop으로 꺼내면서 삭제합니다. `/me`와 이력 조회는 계속 정상으로 동작합니다. 오류는 try 안에서 발생하므로 기존 RequestError 처리를 거칩니다.

실패 때 pending을 지우지 않고 오류 안내를 남긴 뒤 rerun합니다. 다시 그린 입력창은 pending이 있으므로 비활성화됩니다. 재시도는 같은 request_id를 사용합니다. 서버는 이미 저장된 번호라면 기존 결과를 돌려주므로 응답을 놓친 요청을 다시 확인할 수도 있습니다. 이번 버튼만으로는 저장 후 응답 유실 상황을 재현한 것이 아닙니다.

### 수정 전 위치와 이번에 바꿀 함수

`handle_chat_error()`는 `st.session_state["pending"] = None`을 실행합니다. 실패 직전에 보관한 질문을 지우므로 다시 보내기 버튼이 사라집니다.

수정할 파일은 **lesson07/main.py**입니다. 아래 함수로 교체합니다. 전체 실행 코드는 [main.py](main.py)에 있으며, 여기는 수정할 부분만 표시합니다.

```python
def handle_chat_error():
    st.session_state["error"] = "AI 요청에 실패했습니다. 서버 상태를 확인하세요."
    st.rerun()
```

참고: [Streamlit 공식 대화 예제](https://docs.streamlit.io/develop/tutorials/chat-and-llm-apps/build-conversational-apps), [위키독스 챗봇 예제](https://wikidocs.net/352332).

## 3. 코드 제공

### 준비와 실행

Windows CMD에서 현재 차시 폴더로 이동합니다. 기존 수업 가상환경을 사용하거나 처음 한 번만 생성·활성화합니다. [서버 실행 안내](../BACKEND_GUIDE.md)에서 이번 차시에 해당하는 서버를 먼저 준비합니다.

```bat
cd /d C:\AI4\MultiTurn_02_08\lesson07
python -m pip install -r requirements.txt
copy .env.example .env
python -m streamlit run main.py --server.address 127.0.0.1 --server.port 8501
```

패키지를 설치하고 설정 예시를 복사한 뒤 화면 서버를 실행합니다. **기존 .env가 있으면 복사로 덮어쓰지 말고 값을 확인**합니다. 파일 미리보기가 아니라 브라우저의 http://127.0.0.1:8501 에서 실습합니다. 종료는 이 CMD에서 Ctrl+C입니다.

화면 폴더의 .env에는 `API_BASE_URL=http://127.0.0.1:8000`을 사용합니다. 모델 키와 DB 접속 값은 백엔드 폴더의 .env에만 둡니다. 이번 차시는 **backend06**와 연결합니다. 6차시에서 쓰던 backend06을 계속 켜 두며 서버를 교체하지 않습니다.

### 실행해 보고 한 곳 바꾸기

1. 로그인하고 `실패 실습 A`, `실패 실습 B` 두 대화를 만듭니다. 첫 번째 대화를 선택하고 기존 말풍선 개수를 확인합니다. 서버는 모두 켜 둡니다.
2. **실패 후 재시도 실습**을 펼쳐 **다음 AI 요청 한 번 실패시키기**를 누릅니다. 질문 `실패한 뒤에도 이 질문을 다시 보내고 싶어.`를 전송합니다. 시작 코드에서는 오류 안내 뒤 pending을 지우므로 입력창이 열려 있고 재시도 버튼이 없습니다.
3. lesson07/main.py의 `handle_chat_error()`만 위 코드로 교체합니다. 다시 실패 버튼을 누른 뒤 같은 질문을 전송합니다.
4. 오류 안내 뒤 **입력창이 잠기고 확인 중인 질문과 요청 번호가 보이는지** 확인합니다. 이번 버전은 오류 처리에서 rerun하므로 화면 다시 실행을 따로 누르지 않습니다. 실패한 질문·답변은 이력에 추가되지 않아야 합니다.
5. 두 번째 대화로 바꾸면 **미확정 질문이 다른 대화에 있습니다. 원래 대화로 돌아가세요.**가 표시됩니다. 입력창도 계속 잠겨 있습니다.
6. 첫 번째 대화로 돌아와 **같은 질문 다시 보내기**를 누릅니다. 실패 예약은 이미 소모됐으므로 다시 실패 버튼을 누르지 않습니다. 성공 후 입력창이 열리고 질문·답변 한 쌍만 추가되어야 합니다.
7. 다시 실패를 만든 뒤 **계정 바꾸기 / 로그아웃**을 누르면 미확정 질문은 삭제됩니다. 계정 전환에는 미작성 경고가 구현되어 있지 않습니다.

정확한 AI 문장은 달라질 수 있습니다. 먼저 펼친 모델 입력과 말풍선 개수를 확인한 뒤 답변이 앞선 내용을 참고했는지 읽습니다.

<details>
<summary>실행이 멈추거나 화면이 비어 있을 때</summary>

- 다운로드한 파일의 미리보기 대신 CMD에 표시된 Streamlit 주소를 엽니다.
- 제목도 보이지 않으면 브라우저에서 Ctrl+Shift+R을 누르고 실행 CMD의 오류를 확인합니다. [공통 문제 해결](../TROUBLESHOOTING.md)을 참고합니다.
- 제목과 연결 오류가 보이면 이번 차시의 backend와 모델 서버 CMD를 확인합니다. 로그인 차시는 Redis도 실행 중이어야 합니다.
- 설정 파일은 실행한 폴더의 .env를 읽습니다. 다른 차시 .env를 편집한 것은 아닌지 확인합니다.
- 연결·모델 오류는 성공 기록에 넣지 않습니다. 로그인 만료 안내가 나오면 다시 로그인합니다.

</details>

### AI와 함께 오류 원인 찾기

실습 버튼이 동작하지 않는다면 키 이름을 보내는 쪽과 읽는 쪽에서 비교합니다. `fail_next_chat`에 철자가 하나라도 다르면 다른 보관함입니다. `raise httpx.ConnectError(...)`는 반드시 api 함수의 try 안에 있어야 기존 except가 처리합니다. 서버 전체를 끄는 방법으로 바꾸지 않습니다.

### 복습 과제

실패 직전과 재시도 후 말풍선 개수를 비교하세요. 성공 후 정확히 두 개만 늘어났는지 확인하고 pending을 성공 뒤에만 지우는 이유를 설명하세요.

수정한 함수와 직접 확인한 결과를 짧게 남깁니다. 실제 계정 정보나 대화 원문 전체를 제출하지 않습니다.
