## 2. 중요 알고리즘 및 코드를 읽을 때 반드시 알아야 할 내용

### 화면 조작 후 main.py가 다시 실행된다

이 예제에서 메시지를 제출하거나 버튼을 클릭하면 Streamlit이 main.py를 위에서 아래로 다시 실행합니다. 화면의 출력도 다시 만들어집니다. `messages = []`를 파일의 위쪽에 두면 매 실행마다 새 빈 목록을 만들기 때문에 직전에 입력한 문장이 사라집니다.

`session_state`는 **같은 세션의 다음 실행에서도 찾아 쓸 수 있는 보관함**입니다. 값은 Streamlit 서버 쪽 메모리에 있고, 브라우저 탭의 연결과 묶입니다. 브라우저 자체의 영구 저장소는 아닙니다.

### 작은 비교: 매번 빈 목록 만들기와 한 번만 만들기

다음 코드는 설명용 일반 파이썬 예제입니다. 두 번의 실행을 for로 흉내 낸 것이며 Streamlit 서버를 실행하지 않습니다. CMD에서 `python`으로 대화형 모드에 들어가 붙여 넣습니다. 마지막 줄 뒤 Enter를 한 번 더 누르고, 끝나면 `exit()`로 CMD로 돌아옵니다.

```python
inputs = ["안녕하세요", "내 이름은 민수"]
print("매번 초기화")
for text in inputs:
    messages = []
    messages.append(text)
    print(messages)

print("없을 때만 초기화")
state = {}
for text in inputs:
    if "messages" not in state:
        state["messages"] = []
    state["messages"].append(text)
    print(state["messages"])
```

예상 출력:

```text
매번 초기화
['안녕하세요']
['내 이름은 민수']
없을 때만 초기화
['안녕하세요']
['안녕하세요', '내 이름은 민수']
```

첫 방식은 두 번째 입력 직전에 목록을 다시 만듭니다. 두 번째 방식은 `messages`라는 이름이 이미 있으면 기존 목록을 사용합니다. 실제 앱에서는 `state` 자리에 `st.session_state`가 있고, 반복 실행은 Streamlit이 담당합니다. 일반 딕셔너리 자체가 별도 프로그램 실행이나 브라우저 연결을 넘어 값을 보관하는 것은 아닙니다.

### 목록·딕셔너리·초기화·추가의 역할

| 코드/말 | 쉬운 뜻 | 이 화면에서의 역할 |
| --- | --- | --- |
| `[]` | 순서가 있는 빈 목록 | 여러 메시지를 넣을 자리 |
| `{"role": "user", "content": "안녕"}` | 이름과 값을 짝지은 딕셔너리 | 메시지 한 개의 발화자와 내용 |
| `"messages"` | 보관함을 찾는 이름인 키 | 대화 목록을 꺼내는 이름 |
| `if "messages" not in ...` | 그 이름이 없을 때만 실행 | 첫 초기화 뒤 기록을 덮어쓰지 않음 |
| `.append(...)` | 맨 뒤에 한 개 추가 | 기존 메시지를 유지하면서 새 메시지 기록 |
| `for message in ...` | 앞에서부터 한 개씩 꺼내기 | 입력 순서대로 말풍선 표시 |

`role="user"`는 말풍선의 발화자 종류입니다. 인증된 사용자 ID가 아닙니다. 이 차시의 기록은 현재 탭 세션의 입력 목록이며 사용자 계정별 저장 이력은 아닙니다.

### 데이터 바인딩은 데이터를 화면에 연결하는 일

복잡한 기능 이름으로 외우기보다 “목록의 content 값을 말풍선에 표시한다”로 이해합니다. 이 코드에서는 목록이 바뀌는 것만으로 브라우저 화면이 저절로 갱신되지 않습니다. 재실행 중 목록을 읽고 출력하는 구문이 실행되어야 화면에 반영됩니다.

현재 실행 순서는 다음과 같습니다.

1. Streamlit이 파일을 실행하고, messages 키가 없으면 목록을 만듭니다.
2. 비우기 버튼이 눌렸다면 목록을 비웁니다.
3. 이번 실행에서 제출된 text가 있다면 공백을 검사하고 목록에 추가합니다.
4. **추가·삭제를 마친 목록**으로 메시지 수와 말풍선을 그립니다.
5. 파일 끝에서 이번 실행이 끝납니다. 다음 화면 조작이 다시 실행을 시작합니다.

`st.chat_input`은 제출이 없는 실행에서 `None`을 반환합니다. 따라서 `화면 다시 실행` 버튼을 눌러도 이전 입력을 다시 append하지 않습니다. 최종 main.py는 입력 처리를 출력보다 앞에 두므로 별도의 `st.rerun()`을 호출하지 않습니다.

`with st.chat_message(...)`는 이어지는 들여쓴 출력을 하나의 말풍선 안에 배치합니다. `st.text`는 내용을 일반 텍스트로 표시합니다. `st.write`는 메시지 수를 표시하고, `len`은 목록의 항목 수를 셉니다.

### 무엇을 유지하는가

| 조작 | 이 앱의 메시지 목록 |
| --- | --- |
| 메시지 제출 또는 화면 다시 실행 버튼 | 같은 세션의 목록을 유지 |
| 대화 비우기 버튼 | 현재 세션 목록을 빈 목록으로 변경 |
| 주소를 별도 새 탭에서 열기 | 별도 세션의 빈 목록으로 시작 |
| 브라우저 새로고침(F5) | 새 연결로 상태 초기화 |
| Streamlit 서버 종료 후 재시작 | 서버 메모리의 기록을 복원하지 않음 |

이후 로그인 유지도 같은 세션의 재실행 유지부터 다룹니다. 새로고침 뒤 자동 로그인 복원은 별도의 설계입니다. 화면에 로그인 표시가 있다는 사실만으로 API 접근 권한이 검증되는 것도 아닙니다.

외부 접속 설정이 없는 차시이므로 `.env`와 dotenv 패키지는 필요하지 않습니다. API를 연결하는 차시부터 `.env`를 사용합니다.

`-m venv`는 가상환경 생성 모듈을 실행하고 `.venv`는 만들 폴더입니다. `activate`는 현재 CMD가 이 환경의 Python을 사용하도록 바꿉니다. 이후 앞의 경로 확인 명령을 다시 실행해 `lesson01\.venv\Scripts\python.exe`인지 확인합니다. 기존 환경을 재사용했다면 그 환경의 경로가 나오는 것이 정상입니다.

`pip`는 패키지 설치 도구이고 `install`은 설치 동작, `-r`은 뒤의 파일에서 설치 목록을 읽으라는 옵션입니다. `streamlit==1.51.0`처럼 버전을 지정해 이번 실습과 맞춥니다. 이 파일은 모든 하위 의존성을 고정한 잠금 파일은 아닙니다. 설치 완료 또는 `Requirement already satisfied`가 보이면 해당 환경에 설치된 상태입니다.

### 단계 실습을 시작하는 방법

이제 같은 main.py를 작은 기능부터 다시 쌓습니다. **제공된 완성본을 그대로 실행한 것을 단계 실습으로 끝내지 않습니다.** 완성본은 ZIP에 두고, 편집 중인 main.py의 내용을 비운 뒤 1단계부터 작성합니다. 막히면 ZIP의 완성본과 비교합니다. 단계마다 저장하고 화면에서 성공을 확인한 후 다음으로 갑니다. 설치와 다운로드는 아래 실습 시간에 포함하지 않습니다.

### 1단계 — 사라지는 기록 직접 보기 (약 10분)

이번에는 일반 목록으로 문제를 확인합니다. 빈 main.py에 다음 작은 시작 코드를 작성합니다. 이는 완성본이 아니라 비교를 위한 시작 상태입니다.

```python
import streamlit as st
st.title("메시지가 남는 대화 화면")
messages = []
text = st.chat_input("메시지를 입력하고 Enter를 누르세요")
if text:
    messages.append({"role": "user", "content": text})
for message in messages:
    with st.chat_message(message["role"]):
        st.text(message["content"])
```

같은 lesson01에서 앱을 실행하고 `안녕하세요`, `내 이름은 민수`를 제출합니다. **예상 결과:** 두 번째 문장만 남습니다. 이것이 이번 단계의 통과 기준입니다. 둘 다 보인다면 main.py에서 아직 session_state를 사용 중인지 먼저 확인합니다.

### 2단계 — 목록을 session_state에 보관하기 (약 12분)

새로 배울 것은 “없을 때만 초기화”입니다. `messages = []` 한 줄을 다음 두 줄로 교체합니다.

```python
if "messages" not in st.session_state:
    st.session_state["messages"] = []
```

그리고 기존 코드의 `messages.append(...)` 앞부분을 `st.session_state["messages"].append(...)`로, `for message in messages:`를 `for message in st.session_state["messages"]:`로 바꿉니다. 딕셔너리의 role/content와 말풍선 출력은 유지합니다.

코드 변경 전후의 기록은 비교 대상으로 삼지 않습니다. 저장 후 브라우저를 한 번 새로고침해 빈 상태에서 두 문장을 다시 제출합니다. **예상 결과와 통과 기준:** 두 말풍선이 함께 남습니다. 한 문장만 남으면 초기화 두 줄의 if와 들여쓰기를 먼저 확인합니다.

### 3단계 — 새 입력 없이 다시 실행하기 (약 8분)

초기화 블록 바로 아래, chat_input보다 위에 `st.button("화면 다시 실행")` 한 줄을 추가합니다. 버튼은 클릭 시 파일을 다시 실행하므로 이 단계에서는 반환값을 저장하지 않아도 됩니다.

말풍선을 그리는 for 바로 위에는 `st.write("저장된 메시지 수:", len(st.session_state["messages"]))`를 추가합니다. 저장 후 필요하면 두 문장을 다시 입력하고 버튼을 두 번 누릅니다.

**예상 결과와 통과 기준:** 메시지 수가 2이고 말풍선이 늘거나 줄지 않습니다. 수가 늘면 append가 `if text:` 안에 있는지 먼저 확인합니다. `text`는 이번 제출의 임시 값이고 messages는 누적 기록입니다. 둘을 같은 것으로 보지 않습니다.

### 4단계 — 비우기와 공백 처리 확인하기 (약 15분)

먼저 **초기화 블록 다음, chat_input 앞**에 비우기 버튼을 추가합니다.

```python
if st.button("대화 비우기"):
    st.session_state["messages"] = []
```

기록이 있는 상태에서 눌러 메시지 수 0과 말풍선이 사라지는 것을 먼저 확인합니다. 늦게 사라지면 버튼 처리 위치가 for보다 앞인지 확인합니다. 이 버튼이 초기화하는 것은 현재 목록이며 서버를 중지하지 않습니다.

이 확인이 끝나면 `if text:` 안에서 바로 append하던 부분을 수정합니다. 먼저 `cleaned = text.strip()`을 만들고, `if cleaned:` 안에서 content를 cleaned로 append합니다. `else:`에서는 `st.warning("공백이 아닌 메시지를 입력하세요.")`를 호출합니다. 정확한 위치·들여쓰기는 완성본의 chat_input 아래 블록과 대조합니다.

**실행 입력:** 공백만 제출 → `다시 시작` 제출. **예상 결과와 통과 기준:** 공백은 목록에 추가되지 않고 정상 문장 한 개만 남습니다. 일부 브라우저에서 공백 제출 자체를 막으면 정상 메시지·빈 기록을 먼저 확인하고, 공백 분기는 아래 검증 범위를 참고합니다. 통과하지 못하면 content에 text 대신 cleaned를 넣었는지 먼저 확인합니다.

마지막으로 제목 아래에 완성본의 caption 안내를 추가해 이 화면에 AI 답변이나 로그인이 없음을 표시합니다. 별도 새 탭으로 앱 주소를 열어 빈 목록인지 확인하고, 원래 탭 기록은 그대로인지 비교합니다. 이어 원래 탭에서 F5를 눌러 기록이 초기화되는지 확인합니다. 정리·비교는 약 5분으로 마무리합니다.

### 멈추기·다시 시작하기·막혔을 때

앱을 끄려면 실행 중인 CMD에서 `Ctrl+C`를 누릅니다. 다시 실행할 때는 같은 폴더·가상환경에서 `python -m streamlit run main.py`를 사용합니다. 재시작하면 이전 메모리 기록은 복원되지 않습니다.

| 현상 | 먼저 확인할 것 | 복구 |
| --- | --- | --- |
| main.py를 못 찾음 | 현재 폴더 | 앞의 cd 명령으로 lesson01로 이동 |
| No module named streamlit | 실제 Python 경로 | 정상 가상환경 활성화 후 설치 명령 다시 실행 |
| 첫 실행부터 messages 관련 오류 | 초기화 위치·철자 | 키를 읽기 전에 조건부 초기화 배치 |
| 매번 마지막 문장만 보임 | 무조건 빈 목록 대입 여부 | 초기화를 if 블록 안으로 이동 |
| 비운 뒤 한 번 더 눌러야 사라짐 | 비우기 처리 순서 | 출력보다 앞에서 비우기 |
| F5 뒤 기록이 사라짐 | 재실행 버튼과 혼동 여부 | 현재 예제의 정상 수명. 새 문장을 입력해 다시 시작 |

예전 Python/Conda 경로를 못 찾는다면 코드 문제가 아닐 수 있습니다. 먼저 `deactivate`로 기존 가상환경을 해제하고, `where python`, `python --version`으로 외부 Python부터 확인합니다. `where`는 후보 경로 목록 조회입니다. WindowsApps 경로만으로 실패를 단정하지 말고 실제 버전 실행을 확인합니다.

외부 Python이 정상이고 현재 lesson01의 `.venv`가 고장 났을 때만 `ren .venv .venv_backup`으로 이름을 바꿔 보관합니다. `ren`은 이름 변경이며 파일 삭제가 아닙니다. 같은 백업 이름이 있으면 `.venv_backup2`처럼 다른 이름을 사용합니다. 이후 앞의 환경 생성→활성화→실제 경로 확인→패키지 설치 순서로 복구합니다. 부모 폴더의 가상환경을 사용했다면 해당 환경 폴더에서 백업하며, 외부 Python도 실패하면 그 설치 문제부터 해결합니다.

### 검증 범위

Streamlit 1.51.0의 AppTest로 중간 단계와 완성본의 입력 누적, 재실행 유지, 비우기, 독립 세션, 공백 검사, 잘못된 무조건 초기화의 재현·수정을 확인했습니다. 문법·범위 명세·ZIP 안의 교안과 원본 일치도 검사했습니다. AppTest는 브라우저 자동 조작이 아니므로 Windows CMD와 실제 브라우저의 F5·새 탭 동작은 위 절차로 직접 확인합니다. 외부 인증·DB·Redis·모델 호출은 이 차시 검증 대상이 아닙니다.

## 4. Vibe 코딩에 유용한 프롬프트

### 실행 순서를 이해할 때

```text
lesson01/main.py를 읽어 줘. Streamlit으로 실행하는 앱이고,
안녕하세요와 내 이름은 민수를 순서대로 제출한 뒤 화면 다시 실행 버튼을 누른다.
각 실행의 text 값, messages 초기화 여부, append 실행 여부, 최종 목록을 표로 설명해 줘.
st.chat_input의 미제출 반환값과 session_state의 수명은 공식 동작에 근거해 설명해 줘.
코드는 바꾸지 말고, 확인한 사실과 추론을 구분해 줘.
.env 값·토큰·개인정보를 요청하거나 출력하지 마.
```

### 기록이 사라지는 문제를 찾을 때

```text
lesson01/main.py를 확인해 줘. python -m streamlit run main.py로 실행했고
첫 입력은 안녕하세요, 두 번째 입력은 내 이름은 민수다.
두 번째 입력 후 마지막 말풍선만 남는다. 두 문장이 모두 남아야 한다.
초기화 조건·들여쓰기·입력 추가·출력 순서부터 추적하고 원인을 한 가지씩 설명해 줘.
최소 변경으로 수정하고, 기존의 비우기 기능과 공백 검사는 유지해 줘.
전역 변수나 파일 저장으로 우회하지 말고 session_state로 해결해 줘.
같은 두 입력과 화면 다시 실행 버튼으로 수정 전후를 비교해 줘.
실행하지 못하면 미검증이라고 밝혀 줘. 비밀값이나 대화 원문 전체를 요구하지 마.
```

### 복습 과제

1. 현재 목록을 비우지 않고 **마지막 메시지 한 개만 취소하는 버튼**을 추가합니다. chat_input보다 앞에 두고, 목록이 있을 때만 `pop()`으로 마지막 항목을 제거합니다. pop은 목록의 마지막 항목을 꺼내며 목록도 바뀝니다. `하나`, `둘`을 입력한 뒤 한 번 누르면 `하나`만 남고, 빈 목록에서 눌러도 오류가 없어야 합니다. 수정 코드와 두 상황의 화면, 조건이 필요한 이유 한 문장을 남깁니다.
2. 선택 과제: `내용을 입력하세요`처럼 입력 안내 문구를 바꾸되, 입력한 문장과 저장된 문장을 구분해 설명합니다. 문구 변경 후 기존 유지 동작과 비우기가 동작하는지 확인합니다.

먼저 직접 수정하고, 막히면 위 프롬프트에 현재 증상과 기대 결과를 넣어 힌트를 받습니다. 다음 차시는 과제 완성 여부와 관계없이 시작할 수 있습니다.
