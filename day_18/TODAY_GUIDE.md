# 수업 전 안내: 로그인한 내 기록을 화면에 연결하기

## 오늘 만들 결과물

로그인 후 내 대화를 고르고, 새 문장을 저장한 뒤 다시 확인하는 화면을 만듭니다. 계정을 바꾸면 이전 사용자의 선택과 문장이 새 사용자 화면에 섞이지 않아야 합니다.

설명용 예상 화면: `현재 계정: A의 이메일` 아래에 `학습 메모 · ID일부` 선택 목록과 이전 문장이 보입니다. `이번 주 복습할 내용을 정리하자`를 입력하면 저장 확인 안내와 새 말풍선이 나타납니다. 로그아웃하면 로그인 폼으로 돌아갑니다. B로 로그인하면 B의 목록을 읽습니다.

실제 인증·DB 저장을 사용합니다. 샘플 문장은 수업 준비 때 넣은 합성 기록이며 AI 답변을 생성하는 화면은 아닙니다. 이번에는 새로고침 후 자동 로그인 대신 다시 로그인해서 기록을 복원합니다.

## 오늘의 진행 순서

| 차시 | 붙일 한 가지 | 끝나면 직접 확인할 것 |
| --- | --- | --- |
| 2 | 인증 성공 결과 보관 | 재실행해도 같은 계정 유지 |
| 3 | 로그인 여부에 따른 화면 분기 | 로그아웃 한 번으로 폼 복귀 |
| 4 | 조회 결과를 말풍선에 연결 | DB에 있는 내 문장 표시 |
| 5 | 대화 ID 선택 | 같은 제목의 두 대화 전환 |
| 6 | 저장 후 다시 읽기 | 실제 저장한 문장 한 번 표시 |
| 7 | 만료·장애에 따른 다른 처리 | 만료는 재로그인, 장애는 복구 후 확인 |
| 8 | 사용자 경계·전체 검증 | A→B→A에서 기록 분리·복원 |

각 차시는 로그인·조회 준비 코드 위에 한 가지씩 추가합니다. 차시 안에서도 블록을 덜어 낸 시작 상태에서 순서대로 붙이며 매번 실행 결과를 확인합니다.

## 시작 전 확인

- [BACKEND_GUIDE.md](BACKEND_GUIDE.md)에서 패키지·설정·DB·Redis 준비를 먼저 끝냅니다. 모델 다운로드는 필요 없습니다.
- 같은 Supabase 프로젝트의 수업용 계정 A·B와 로그인 가능한 비밀번호를 준비합니다. 비밀번호는 브라우저 폼에 입력합니다.
- 예시 폴더는 `C:\AI4\Session_State_02_08`입니다. backend CMD와 현재 차시 UI CMD 두 개를 켭니다.
- backend는 이 묶음의 한 버전만 8000 포트에서 실행합니다. 이전 모델 서버·backend06과 혼동하지 않습니다.
- 처음 열 교안은 [lesson02/README.md](lesson02/README.md)입니다. 1차시 파일은 이 묶음에 포함하지 않습니다.

용어를 짧게 확인합니다. **토큰**은 인증을 증명하는 값, **대화 ID**는 대화를 찾는 이름, **데이터 바인딩**은 조회한 값을 화면에 연결하는 일입니다. 자세한 역할과 예제는 각 차시에서 확인합니다.

## 완료 확인

1. 같은 탭에서 로그인·재실행·선택·저장·재조회를 수행합니다. 서버에 저장된 문장만 이력에 표시되어야 합니다.
2. 로그아웃·만료 뒤에는 이전 개인 화면이 사라지고 다시 로그인해야 합니다. DB 문장은 남아 있어야 합니다.
3. A→B→A 전환에서 각자의 목록만 보이고, 응답이 끊긴 저장을 같은 요청 ID로 확인해도 한 행이어야 합니다.

실제 접속 환경에서 확인하지 못한 항목은 완료했다고 표시하지 않습니다. 제작 시의 대역 검증 범위는 교안 3번에 구분되어 있습니다.
